# Формат таблицы задач в Markdown — `task-table@0` (черновик)

> Статус: **черновик**, обсуждаем. Версия в `format:` нужна, чтобы потом менять формат, не ломая старые файлы.

Зачем: выгрузить задачи события одним файлом, чтобы
1. скинуть его в ИИ как контекст;
2. прочитать/поправить руками в любом редакторе (GitHub, Obsidian, VS Code);
3. загрузить обратно в сервис — изменения применятся после предпросмотра.

Живой пример — [`examples/bpmn-hackathon-roadmap.md`](examples/bpmn-hackathon-roadmap.md): лист «Roadmap» нашей таблицы с BPMN-хакатона, переложенный в этот формат.

## Устройство файла

```markdown
---
format: task-table@0
event: "Хакатон …"
exported_at: 2026-10-10T12:00:00+03:00   # для поиска конфликтов при импорте
statuses: [НЕ ГОТОВО, В ПРОЦЕССЕ, ОЖИДАЮ ЗАВИСИМОСТЬ, ГОТОВО]
members: [Паша, Ярослав, Анастасия, Никита, Все]
fields:                                    # свои колонки события
  - key: area
    title: Зона ответственности
    type: select                           # text | select | multiselect | date | url
    options: [ML/LLM, BackEnd, FrontEnd, Смежное]
---

# Название события

## День 1 {start=2026-09-28}

### Организация и репозиторий

| ID | Задача | Ответственный | Статус | Зависит от | Зона ответственности | Комментарий |
|---|---|---|---|---|---|---|
| D1-01 | Разбор задачи всей командой | Все | ГОТОВО | — | Смежное | |
```

## Правила

**Структура = дерево.**
- `#` — событие (один на файл).
- `##`, `###`, … — группы; уровень заголовка = уровень вложенности. «День 1» и «Организация и репозиторий» — обе группы, просто одна с датой, другая без.
- Необязательные атрибуты группы — в фигурных скобках в конце заголовка: `{start=2026-09-28 end=2026-09-29}`.
- Таблица под заголовком — задачи этой группы.

**Колонки.**
- Обязательные: `ID`, `Задача`.
- Встроенные (узнаются по названию): `Ответственный`, `Статус`, `Зависит от`, `Начало`, `Срок`, `Комментарий`.
- Остальные сопоставляются со `fields[].title` из шапки. Незнакомая колонка → предупреждение в предпросмотре и предложение создать текстовое поле.
- Порядок колонок любой.

**Ячейки.**
- Пусто, `-` или `—` — значение не задано.
- Несколько значений — через запятую: `D1-03, D1-05`.
- `|` внутри текста — `\|`, перенос строки — `<br>`.
- Значения `select` и `Статус` должны быть из списков в шапке; иначе — предупреждение (как выпадающий список с проверкой данных в Google Таблицах).

## Импорт

1. Файл разбирается в каноническую модель `TaskTable` (та же модель, что у экспорта и будущих адаптеров).
2. Строится **ChangeSet** — список правок относительно базы:
   - строки сопоставляются по `ID` → «изменить»;
   - новый `ID` или пустой `ID` → «создать» (пустому ID сервис выдаст номер);
   - задача есть в сервисе, но нет в файле → по умолчанию **не удаляется**, в предпросмотре можно отметить «удалить отсутствующие»;
   - задача менялась в сервисе позже `exported_at` → «конфликт», решает человек.
3. Человек смотрит предпросмотр и применяет всё или часть.

## Что дальше (не в v0)

- «Карточный» вариант для длинных описаний: задача — заголовок `#### D1-02 …` + список полей + свободный текст.
- Другие листы таблицы («Требования и проверки», «Вопросы экспертам») — пока отдельные MD-документы в базе знаний события; упоминания `D1-05` в тексте превращаются в ссылки на задачи.
- Экспорт «контекста для ИИ»: база знаний события + эта таблица одним файлом.
