# ADR-0001. Где живёт таблица задач события

- **Статус:** открыт — решаем после этапа 1 (когда будет таймлайн и прототип своей таблицы)
- **Дата:** 2026-10-10

## Контекст

Событие (хакатон, конференция) содержит десятки задач с ответственными, статусами и зависимостями — как наша таблица с BPMN-хакатона. Вопрос: где эти задачи хранятся и редактируются.

Что **уже согласовано** и не зависит от решения:
- экспорт в Markdown нужен в любом случае — чтобы скидывать задачи и базу знаний в ИИ;
- у события должна быть возможность прикрепить ссылку (на таблицу, пост в TG, репозиторий);
- интерфейс важнее технологии: удобно, без перегруза.

## Варианты

### A. Своя таблица в сервисе + импорт/экспорт MD
Задачи — строки в PostgreSQL, таблица отрисовывается в нашем UI, MD — формат обмена (см. [`task-table-md.md`](../formats/task-table-md.md)).

- ➕ Задачи — часть модели: видны на таймлайне, в «Сегодня/завтра», доступны ИИ-ассистенту, есть зависимости и сводка без формул.
- ➕ Свой интерфейс под наши сценарии, быстрая работа на больших таблицах.
- ➖ Таблицу надо сделать: редактирование ячеек, выпадающие списки, сортировка, вставка из буфера.

### B. Google Таблица по ссылке
Событие хранит ссылку на Google Таблицу, кнопка «Открыть таблицу».

- ➕ Почти бесплатно: готовая привычная среда, совместное редактирование, формулы.
- ➖ Задачи не видны сервису: ни таймлайна по задачам, ни «задач на завтра», ни контекста для ИИ без ручного копирования.
- ➖ Данные разъезжаются по двум местам.

### C. Гибрид: своя таблица + мост в Google Таблицы
Основное хранение — как в A, плюс адаптер Google Sheets: «Выгрузить в Google Таблицу» и/или «Загрузить из Google Таблицы».

- ➕ Кому удобнее в Google — работает там, сервис при этом знает задачи.
- ➖ Двусторонняя синхронизация — самая дорогая часть (конфликты, квоты API, доступ через сервисный аккаунт или OAuth). Односторонние импорт/экспорт — заметно проще.

### D. Дешёвый мост без Google API
Импорт `.xlsx`/`.csv`: Google Таблица скачивается как файл (или по ссылке на CSV, если таблица открыта по ссылке) и загружается через тот же предпросмотр изменений.

- ➕ Переносит все наши старые таблицы, не требует ключей Google.
- ➖ Это перенос, а не синхронизация.

## Сравнение

| Критерий | A | B | C | D |
|---|---|---|---|---|
| Трудозатраты | средние | минимальные | высокие (двусторонняя) | низкие |
| Задачи на таймлайне и в «Сегодня» | да | нет | да | да (после импорта) |
| Контекст для ИИ одной кнопкой | да | нет | да | да |
| Привычная среда Google | нет | да | да | частично |
| Зависимость от Google API | нет | нет | да | нет |

## Как архитектура держит вопрос открытым

Вопрос целиком локализован в модуле **Interchange** (см. [ADR-0002](0002-modular-monolith.md)), ядро Planning от него не зависит.

1. **Ссылки у любого узла** (`Link` с типом `google_sheet`, `tg_post`, `repo`, …) появляются в Planning на этапе 1. Вариант B доступен сразу и никому не мешает.
2. **Каноническая модель `TaskTable`** (колонки + строки) лежит в `Modules/Interchange/…/Application`. Все форматы конвертируются только в неё и из неё.
3. **Порты** `ITaskTableExporter` / `ITaskTableImporter`. У каждого формата своя папка-адаптер в `Modules/Interchange/…/Adapters/`:
   - `Markdown/` — делаем в любом случае;
   - `GoogleSheets/` — слот под вариант C, пока пустой;
   - `Xlsx/` — вариант D.
4. **Импорт всегда идёт через ChangeSet** — тот же предпросмотр, что у ИИ-ассистента. Interchange только предлагает правки, применяет их Planning. Новый источник данных не требует нового UI.
5. У события есть поле **`taskSource`**: `internal` | `external_link`. UI показывает либо свою таблицу, либо карточку со ссылкой. Чтобы поменять решение для конкретного события, достаточно переключить поле.

## Как решаем

После этапа 1:
1. Показать прототип своей таблицы.
2. Провести одно реальное событие (ближайший хакатон) в выбранном варианте, второй держать как запасной.
3. Сравнить по критериям: скорость заведения 30+ задач, удобство с телефона, сколько раз приходилось копировать руками, сколько времени ушло на разработку.

Решение записать сюда, статус → «принят».
